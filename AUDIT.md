# Проверка приложения

Базовая версия: ce4ea31d0e41d6c41cba6e50bf7ffbb22409bf5f.

## Выполненные проверки

- Загружены все 39 JavaScript-файлов, HTML и CSS.
- Проверен синтаксис JavaScript после удаления модульных import/export для проверки через V8 Function. Это не заменяет полноценную проверку загрузки ES-модулей.
- Все статические относительные импорты ведут к существующим файлам.
- Все модули js достижимы от app.js; целиком неиспользуемых модулей по этому графу не обнаружено.
- В index.html не найдены повторяющиеся id и отсутствующие локальные ресурсы.
- В браузере на опубликованной базовой версии открылись главная, задачи, контакты, финансы, база знаний. Проверка выполнялась в локальном режиме на пустых данных.
- Девять регрессионных утверждений прошли на изменённом коде: ожидание commit, отклонение abort, распространение ошибки сохранения четырьмя разделами, единственный сетевой запрос при промахе кэша и запись в текущий кэш. Тело тестов выполнено в изолированной JavaScript-среде с моделями IndexedDB/Cache API; это не реальные браузерные транзакции.
- Повторный запуск тестов: node tests/regression.mjs (полный запуск этой команды в Node в текущей среде не выполнялся).

## Исправления

- Одиночные операции IndexedDB завершаются после transaction.complete, обрабатывают abort.
- Ошибки записи при слиянии заметок, контактов, финансов, базы знаний передаются вызывающему коду; синхронизация не считает такой шаг успешным.
- Ошибка записи при применении удалений контактов не подавляется.
- Очистка текста существующей заметки сохраняется.
- Service worker ищет только в текущем кэше: старый глобальный rl-v316 больше не подменяет обновлённые файлы.
- На промахе кэша выполняется один запрос; фоновая запись удерживается waitUntil.
- Установка service worker не завершается успешно при неполном наборе обязательных ресурсов.
- Удалены неиспользуемые heatMax, toScreen и пустой finally.

## Структура и оставшиеся риски

- CSS style.css около 378 КБ, kb.js около 92 КБ, finance.js около 62 КБ, week.js около 59 КБ. Крупные файлы объединяют несколько обязанностей. Массовое разделение файлов требует отдельных тестов поведения и в этом коммите не выполнялось.
- snapshot.js зависит от модулей с интерфейсом. Разделение слоя данных и представления остаётся задачей рефакторинга.
- Ряд изменений сначала меняет память, затем пишет в базу. При ошибках запись теперь отклоняется, но единый механизм отката состояния и уведомления пользователя ещё требуется.
- Вход в другой аккаунт при сохранённых локальных данных требует отдельной проверки изоляции.
- Обработка недоверенного HTML, URL вложений и серверная авторизация требуют отдельного аудита безопасности.
- Старые общие кэши намеренно не удаляются: они могли использоваться другими приложениями домена.

## Границы результата

Это расширенная статическая проверка и ограниченная функциональная проверка, а не доказательство отсутствия ошибок.
Не выполнены полная матрица пользовательских сценариев, реальные многопользовательские конфликты, проверка двух устройств, реальная потеря квоты IndexedDB, мобильные браузеры, импорт всех банковских форматов и реальная облачная синхронизация.
Код Google Apps Script отсутствует в репозитории. Развёрнутые Яндекс/Cloudflare функции и доступ к облачным аккаунтам не проверялись.
